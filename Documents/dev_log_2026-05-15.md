## Features Implemented

### 1. Notification & Activity Log System

**Backend:**
- `ActivityLog` model — tracks who did what, on which entity, and when
- `Notification` model — user-scoped alerts with read/unread state and type
- `INotificationService` / `NotificationService` — CRUD for user notifications with polling support
- `IActivityService` / `ActivityService` — logs actions to ActivityLogs table with user join
- `NotificationsController` — GET, PUT /{id}/read, PUT /read-all, GET /unread-count
- `ActivitiesController` — GET with configurable limit
- Activity hooks wired into CustomersController and LeadsController (Create/Update auto-logs)

**Frontend:**
- `Header.jsx` — Rebuilt with live Notification Bell dropdown
  - Polls /api/notifications every 30 seconds
  - Shows unread badge (red dot)
  - Mark All Read button
  - View Activity Log link footer
  - Click-outside to close (ref-based)
- `ActivityLog.jsx` — Dedicated full-page activity feed at /activity
  - Color-coded action badges (Created=green, Updated=blue, Deleted=red)
  - Entity-type icons (Customer = blue user, Lead = purple briefcase)
  - Timestamp per entry, empty state illustration
- `Sidebar.jsx` — Activity Log nav item added
- `App.jsx` — /activity route registered

### 3. Professional CRM Settings Panel (9 Sections)

### Features & Fixes Implemented

#### 1. Customer Deletion & UI Improvements
- **Backend Fix**: Updated `CustomerRepository.cs` to explicitly delete related notes before deleting a customer, preventing SQL foreign key violations.
- **Frontend UI**:
  - Made "Edit" and "Delete" buttons in the customer details pane always visible (removed hover requirement).
  - Added a "Quick Delete" trash icon to each customer in the left list (visible on hover).
  - Added a "Delete" button inside the **Edit Customer** modal for better accessibility.
- **Robustness**: Added 401 Unauthorized handling to all fetch calls. If a session expires, the user is now automatically redirected to the login page.

#### 2. Role-Based Access Control (RBAC) Full Implementation
- **JWT Fix**: Updated `AuthController.cs` to include the user's roles in the JWT token claims.
- **Seeding**: Updated `Program.cs` to ensure a default admin account exists (`admin@crm.com` / `Admin@123`) and has the "Admin" role assigned.
- **Frontend Integration**:
  - Normalized `useAuth.js` to provide a singular `role` property.
  - Enabled the **Roles & Access** section in `Settings.jsx` for Admin users.
  - Sidebar now displays a "Logged as [Role]" badge for clarity.
